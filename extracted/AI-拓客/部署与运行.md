# 部署与运行

## 1. 环境要求

- **Node.js ≥ 22.5**（项目在 Node 22.22.2 验证通过）
  - 数据层使用 Node 内置 `node:sqlite`，**启动必须带 `--experimental-sqlite` 标志**；`npm start` 已包含该标志，直接 `node server.js` 会因缺少标志报错。
  - 仍是零依赖，**无需 `npm install`**。
- 一个 **DeepSeek API Key**（AI 创作 / 私信解析 / 意向分级）
- 一个 **高德地图 Web 服务 Key**（地图获客；在 高德开放平台 控制台申请，选"Web 服务"类型）
- 联网（调用上述两家 API）

## 2. 启动

```bash
cd ai-tuoke

# 1) 准备密钥（不要直接改 .env.example，复制一份）
cp .env.example .env
#   用编辑器打开 .env，填入：
#   DEEPSEEK_API_KEY=sk-xxxx
#   AMAP_KEY=你的高德Key

# 2) 启动（任选其一）
npm start                                # 推荐：等价于 node --experimental-sqlite server.js
node --experimental-sqlite server.js     # 等价写法

# 3) 浏览器访问
#   http://localhost:3000
#   默认登录：admin / admin123（管理员）、sales / sales123（销售）

# 4) 换端口
PORT=3100 npm start
```

> **前端改完记得强刷**：浏览器按 `Ctrl+Shift+R`（或 `Ctrl+F5`）清缓存。项目已用 `app.js?v=10` / `style.css?v=10` 做版本后缀，改完前端建议同步递增该版本号。
>
> **会话为内存存储**：服务重启后需重新登录，这是当前设计（无持久化 session）。

## 3. 配置说明（`.env`）

| 变量 | 作用 | 必填 |
|---|---|---|
| `DEEPSEEK_API_KEY` | AI 大模型调用 | ✅ |
| `DEEPSEEK_BASE_URL` | DeepSeek 网关，默认 `https://api.deepseek.com` | ⭕ |
| `DEEPSEEK_MODEL` | 模型名，默认 `deepseek-chat` | ⭕ |
| `PRODUCT_NAME/DESC/...` | 产品业务配置（前端设置页也可改） | ⭕ |
| `AMAP_KEY` | 高德 Web 服务 Key（仅后端调用） | ✅（用地图获客时） |
| `PUBLIC_BASE_URL` | 公网 HTTPS 地址（平台接入 Webhook 用） | 仅真实接入时 |
| `DOUYIN_CLIENT_ID/SECRET` | 抖音开放平台凭证 | 仅真实接入时 |
| `XHS_CLIENT_ID/SECRET` | 小红书开放平台凭证 | 仅真实接入时 |

> **配置优先级（重要）**：`data/settings.json`（设置页保存的值）**优先于 `.env`**。
> 为避免"页面存了测试值就永远覆盖 `.env`"这类事故，后端已加两道防护：
> 1. 空值 / 纯问号 / 含 `U+FFFD` 的存盘值**不再覆盖** `.env`；
> 2. 保存接口会拒绝占位密钥（`sk-test` / `demo` / `xxx` 等）与过短的 key，返回 400 并给出提示。
>
> 设置页每个配置项下方会显示「当前来自 .env / 页面配置」，排查 AI 失效时先看这里。

## 4. 数据在哪里

- **主库**：`ai-tuoke/data/app.db`（SQLite，WAL 模式，配套 `app.db-wal` / `app.db-shm`）
  - 存：客户、跟进记录、话术模板、AI 历史、平台线索、平台 token、用户账号
- **页面保存的配置**：`data/settings.json`（不存在则表示配置全部来自 `.env`）
- **演示模块（仍为 JSON）**：`data/xiaoguan.json`（AI销冠）、`data/kefu.json`（AI客服）、`data/renshi.json`（AI人事）
- **备份 / 导出**：`data/backups/<时间戳>/`、`data/exports/`

> 这些文件含真实业务数据与账号信息，**不要提交到 git**（见 `.gitignore`）。

### 常用运维操作

```bash
# 手动备份（也等价于设置页「一键备份」）：复制整个 data 目录
cp -r data "backup-data-$(date +%Y%m%d-%H%M%S)"

# 直接查看客户数（需带标志）
node --experimental-sqlite -e "console.log(require('./db.js').getCustomerStats())"
```

> ⚠️ **降级/回滚前先备份**：`data/app.db` 若已启用 WAL，请把 `app.db`、`app.db-wal`、`app.db-shm` **三个文件一起**复制，单独拷 `app.db` 可能丢失还在 WAL 里的数据。
>
> ⚠️ **不要在服务运行时手动删除 `data/app.db*`**：连接仍持有文件句柄，删除会造成数据丢失。需要清空数据请用设置页的「数据重置」（自动先备份、事务化清空、保留账号与配置）。

## 5. 端口被占用怎么办

```bash
# 查占用 3000 的进程
netstat -ano | grep ":3000"
# 改端口：用环境变量（推荐，不必改代码）
PORT=3100 npm start
```

## 6. 平台接入：本地自测 vs 真实接入

- **本地自测**：左侧「平台接入」→ 点「模拟推送」，会走真实的 AI 意向分级链路，无需任何凭证/公网。
- **真实接入（合规路径）**：
  1. 你的账号须为 **抖音企业号 / 小红书专业号**，并在开放平台审批「私信读取 / 评论读取」权限；
  2. 在 `.env` 填好 `DOUYIN_*` / `XHS_*` 与 `PUBLIC_BASE_URL`（必须是公网 HTTPS，Webhook 推不到 `localhost`）；
  3. 把服务部署到该公网地址，点「登录」跳转官方授权页，授权后平台通过 Webhook 把私信/评论推送给本服务。

> ⚠️ **严禁**用爬虫 / 模拟点击获取私信或评论——既违规违法，也违反本项目底线。

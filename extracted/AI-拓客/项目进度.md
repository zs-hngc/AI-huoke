### ✅ 稳定性加固（阶段 12，2026-09-21）
1. **配置失效修复（P0）**：`data/settings.json` 的残留测试值（`sk-test`、乱码 `"????"`）会永久覆盖 `.env`，导致 AI 功能必然 401 且页面上看不出原因。
   - 新增 `isUsableSettingValue()`：空值 / 纯问号 / 含 `U+FFFD` 的文件值**不再覆盖** `.env`。
   - 新增 `reloadSettings()` 替换 POST 里的 `Object.assign(ENV, next)`，避免 ENV 被历史值污染。
   - 新增 `validateSettingsInput()`：拒绝占位密钥（`sk-test`/`demo`/`xxx` 等）与过短 key，拒绝乱码字段，返回 400 + 可操作提示。
   - `GET /api/settings` 新增 `configSource` 字段，设置页显示「当前密钥来自 .env / 页面配置」。
2. **数据重置接口修复（P1）**：原实现调 `db.prepare()` 而 `db.js` 未导出该方法，**必然抛 `TypeError` 返回 500**；且即使修好，还会把 `settings.json`（配置）和正在使用的 `app.db/-wal/-shm` 一起删掉，并在**清空之后**才做备份（备份出来是空库）。
   - 改为 `db.js` 新增 `resetAllData()`：事务内清空 6 张业务表，**保留 `users` 与配置**；重置后自动恢复 4 条预置话术模板。
   - 顺序修正为「先 `wal_checkpoint` → 再备份 → 再清空」，保证备份保留的是重置前的完整数据。
   - 仅清理演示模块 JSON（`xiaoguan/kefu/renshi`）与遗留 `customers.json`，**绝不触碰** `settings.json`、`*.bak`、`backups/`、`exports/`。
   - 前端改用自定义弹窗（原生 `confirm`/`prompt` 在嵌入式预览中会被拦截），支持「保留登录账号」勾选，并回显清空的记录条数。
3. **密码哈希加固（P2）**：`users` 表原先明文存储（`admin123`/`sales123`）。
   - `db.js` 新增 `hashPassword` / `verifyPassword` / `migratePlaintextPasswords` / `upgradePasswordIfNeeded`，密码以 `sha256:<hex>` 前缀格式存储。
   - **启动时自动迁移**历史明文密码；登录仍兼容旧密码（校验通过后立即升级为哈希），老账号不会被锁死。
   - `upsertUser` 对传入密码自动哈希；未传新密码时保持原密码不变。
   - 说明：`sha256` 为**无盐**哈希，仅防止"直接读库即见明文"；若后续要抗彩虹表 / 离线爆破，应升级为 `scrypt` / `bcrypt`（`node:crypto` 的 `scryptSync` 即可，仍无需第三方依赖）。


## 三、已修复的关键 Bug（供团队避坑）

1. **遮罩挡点击**：新弹窗（custModal/custDrawer）漏写 `style="display:none"`，导致全屏遮罩常驻、侧边栏跳转与删除按钮全被拦截。✅ 已修（所有 `.modal-overlay`/`.drawer-overlay` 新弹窗必须带初始隐藏）。
2. **原生 confirm 被拦截**：嵌入式预览禁用原生 `confirm`，删除静默失败。✅ 已改为自定义确认弹窗 `#confirmModal`。
3. **AI 分级失效**：`classifyIntent` 复用了只解析数组的 `extractJsonArray`，DeepSeek 返回的对象被丢弃、分级全回退默认"中"。✅ 新增 `extractJsonObject` 专用解析。
4. **中文接口测试假象**：命令行中文经 Git Bash（GBK）传给 curl 被损坏成 `U+FFFD`，导致"更新状态没生效"的误判。✅ 结论：**测中文接口必须用 Python 或 UTF-8 终端**，浏览器端 fetch 不受影响。
5. **/api/todos 恒 404**：新接口误插进 `if (pathname.startsWith('/api/customers'))` 块内，而它不以该前缀开头 → 整块跳过。✅ 移到该块之外（顶层）。启示：非 `/api/customers` 前缀的新接口切勿放进 customers 的 startsWith 块内。
6. **导出接口 500（非 ASCII 响应头）**：`Content-Disposition` 的 `filename=` 直接放中文，Node HTTP 层拒绝非 ASCII 头值。✅ `filename=` 保持 ASCII，中文仅走 RFC 5987 `filename*=UTF-8''`。
7. **去重接口被路由误吞**：`/api/customers/dedup` 会被 `/api/customers/:id` 正则命中。✅ 新接口须置于 `:id` 正则**之前**。
8. **配置文件反向覆盖 `.env`（AI 静默失效）**：`mergeSettings = Object.assign({}, env, file)` 让 `data/settings.json` 优先级高于 `.env`，一旦页面保存过测试值（`sk-test`）或乱码值，AI 功能就永久 401，且设置页仍显示"已配置"。✅ 已加可用性校验 + 来源标注（详见阶段 12）。
9. **数据重置双重隐患**：`db.prepare` 未导出 → 必 500；且删除范围包含配置文件与正在使用的 SQLite 文件，**备份还在清空之后做**（等于没备份）。✅ 已改为事务化 `resetAllData()` + 先备份后清空（详见阶段 12）。
10. **密码明文入库**：`users` 表存 `admin123`/`sales123` 明文，且 `upsertUser` 也不哈希。✅ 已改为 `sha256:` 前缀哈希 + 启动自动迁移 + 登录兼容升级（详见阶段 12）。
11. **登录页按钮完全失效（致命，等于永久锁死）**：`app.js` 初始化块里先写 `const authOk = await initAuth(); if (!authOk) return;`，**之后**才绑定 `#loginBtn` 的 click 与回车键。未登录时函数直接 return → 登录按钮/回车**从未绑定**，点击毫无反应且控制台零报错（最难排查的一类）。由于会话存在内存 Map 中，**服务一重启会话即失效**，所以每次重启后台必然触发此 bug，表现为"重启后怎么点登录都没反应"。✅ 已把登录/退出/回车绑定抽成 `bindLoginEvents()` 并**提前到登录态判断之前**执行；登录成功后的初始化抽成幂等 `initAfterAuth()`，顺带修掉同一 early-return 造成的第二处问题：**手动登录后设置页按钮事件未绑定**（点"测试连接/重置数据"无反应）。教训：**登录页自身的事件绑定绝不能放在鉴权门之后**。
